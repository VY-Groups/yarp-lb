# Distributed VIP admission (persistent Raft owner)

This extends the local VIP guard. A virtual socket can opt in with requireLocalAddressPresence=true, vipFleetId, vipQuorumConfigPath (absolute private file), and vipOwnershipEpoch (positive exact etcd modification revision). All sockets on that VIP must use the same parameters; the primary traffic and management IPs cannot be shared. Scope is uppercase SHA256 over UTF-8 gatewaycore-adc-vip-v1, LF, fleet ID, LF, canonical IP. The existing authenticated FleetQuorum transport uses three distinct pinned HTTPS Raft member identities, independent CA, and client mTLS. Use a unique client certificate/private key per gateway; the reader needs range-only rights to the dedicated /gatewaycore/adc-vip/v1/<scope> key. Never distribute one reader credential to two nodes.

The owner key is persistent (no TTL), created by an independent writer using create-revision CAS, with ASCII value vip_ followed by uppercase SHA256 of the owning client's DER certificate. The exact key mod_revision is the configured epoch. Overwrites and expiring leases are refused. Every poll must confirm the same state from a majority; loss of majority, wrong owner, wrong epoch, stale local sample or incomplete interface observations denies new requests before routing. A read timeout cannot extend the local freshness window. This is deliberately NOT automatic failover: transfer requires external owner isolation, confirmed address withdrawal, authenticated CAS ownership transfer, durable recovery, and supported host address manipulation. Do not delete or reassign this key just because a node stopped responding. Existing in-flight requests are not revoked. No writer or privileged mutation runs in the shipping gateway. Keep the previous private listener configuration and use independently approved maintenance/rollback procedures; do not disable distributed admission while a peer may own the VIP.

The existing disposable real Raft fixture checks correct owner, wrong credential, wrong epoch/scope, single-member loss, and quorum loss. Local guard regression checks both authority and local address must be confirmed. Physical and automated takeover acceptance remain outstanding.
