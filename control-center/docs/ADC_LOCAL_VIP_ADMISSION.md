# Opt-in local VIP admission guard

In the private listener configuration set requireLocalAddressPresence: true on an individual virtualServices entry. Omitted or false preserves legacy behavior. Restart through approved maintenance. The gateway observes local OS interfaces once per second and admits new requests only if a unique up interface owns the exact address in a complete snapshot less than three seconds old. Initial, stale, incomplete, failed, down, missing or duplicate observations return 503 with no-store before proxy routing. Legacy sockets and management are unaffected. Existing in-flight requests are not revoked. The inventory UI displays admission status.

The real listener CI test opts into a temporary disposable loopback /32 addition/removal, verifying denial, recovery and withdrawal, with cleanup in finally. Local observation is not authenticated cross-node quorum, fencing, VIP assignment, ARP/ND convergence or failover acceptance. Never rely on this to prevent two nodes owning an address. Rollback: restore the reviewed prior private listener file and restart only after confirming external ownership; disabling the guard removes this safety layer. No privileged command runs in the shipping gateway; the test alone modifies a disposable runner with explicit opt-in.
