## Implemented in this PR (awaiting exact-head acceptance)
- Weighted least outstanding HTTP request selection in shipping runtime, reviewed draft validator and UI, with pure and real L7 acceptance tests.
- ADC service map on Overview, derived from actual route-to-cluster-to-destination configuration including disabled members, policies, unresolved references and unreferenced groups. Distinguishes draft/configured state from live traffic and routes through existing authorized editors. This is not the new VIP/object persistence model or a full ADC navigation redesign.

- L4 weighted rotation (TCP and new UDP sessions) and weighted least TCP connections added in engine and signed staging, with real socket acceptance. Exact-head verification pending; L4 dashboard configuration editor and runtime rollout remain incomplete.

- L7 cyclic weighted round robin added through existing reviewed cluster editor/API, runtime and real request tests. Stable weights/membership give exact complete-cycle ratio; not smooth weighted rotation or fleet-shared scheduling. Existing weighted-random scratch span explicitly initialized to zero so draining entries never consume tickets.

- Guided HTTP active-monitor editor and snapshot reuse across service groups, retaining unrelated passive health and metadata. Browser regression covers bounded timing and copied configuration. Persistent shared monitors, compound protocol probes and fleet runtime validation remain pending.

- FastestResponse L7: local EWMA of successful GET/HEAD completion latency, 60-second expiry, weak-reference state, one-in-eight exploration and drain exclusion. No retries or synthetic traffic. Full-response timing includes client/streaming effects; use homogeneous short-response workloads. Not fleet-shared or L4 response-time selection. Real delayed-origin and drain acceptance added; exact-head CI pending.

- Persistent monitor reference contract (first increment): cluster metadata `ADC.HealthMonitorSource` identifies one existing owner group; the reviewed API rejects missing sources, chains/cycles, disabled or out-of-range source settings and divergent active-monitor snapshots or thresholds. The complete approved payload contains both references and materialized YARP configuration. Source updates must explicitly include every linked group. Automatic propagation, guided assignment UI, standalone profile objects, compound probes and fleet-agent validation remain outstanding. Exact-head CI pending.

- Guided shared monitor assignment now offers independent copy or persistent link; source monitor editor propagates changes to every linked group in the same unsubmitted draft; linked groups can unlink retaining their last snapshot. Source deletion/disable/rename guards and linked editing guards added. Advanced JSON remains subject to server validation; no automatic mutation of approved/live configuration, independent profile registry, compound probes or fleet-agent validation yet. Browser acceptance added; exact-head CI pending.

- Compound diagnostics (not active routing health): saved cluster metadata ADC.Diagnostics.CompoundMode (AND/OR), optional ADC.Diagnostics.SecondaryPath, configured primary readiness path and TCP connection to the existing backend host/port. Bounded parallel checks with three-second shared timeout, same-origin HTTP paths, no redirects or cookies in diagnostic client, individual outcomes via existing authorized probe endpoint. Reviewed validator rejects invalid mode/path. Automated loopback and aggregation tests added. No live destination eligibility changes, dedicated UI, standalone profile or fleet runtime acceptance claimed.

- PR #565 review scope correction: the compound diagnostics are strictly on-demand, not active eligibility. Existing real Control Center API acceptance now submits and independently approves a loopback-only diagnostic cluster, calls the actual authenticated POST /admin/api/probe, checks Viewer/CSRF denial, AND failure/success, OR partial success, three-second stalled response deadline, upstream socket closure on deadline and actual downstream client disconnect before deadline, and approved fixture cleanup. Fresh CI and independent review are required; no pass claimed yet.

- Opt-in active compound health (follow-up): `ADC.Health.CompoundMode` AND/OR and `ADC.Health.SecondaryPath` require native active monitoring, distinct bounded paths and `HealthyAndUnknown`. TCP must connect and AND requires both HTTP checks, OR requires at least one HTTP success. Native YARP scheduler, configured cluster client/TLS, probe timeout and health-policy hysteresis are retained. Ordinary requests are not duplicated; unconfirmed or passively unhealthy destinations are excluded before affinity. Proxy and custom Health overrides are refused in this mode. No guided editor, stale-generation fencing, real traffic/fleet acceptance or physical certification claimed. Exact-head CI and review pending.

- Active compound evidence fencing: successful probe evidence is scoped to immutable YARP cluster and destination models, stale-generation evidence is not eligible, older completions cannot overwrite newer completed failures, and evidence expires. This intentionally fails closed on any completed failed compound probe, even before configured fall hysteresis; native health must also be healthy. Real two-origin AND/OR failover, all-down 503 and recovery test stages added to the existing L7 harness. Exact-head CI, fleet and independent review still required.

- Independent monitor profile registry: bounded, validated named HTTP/compound snapshots stored with revisioned reviewed configuration, exposed by state, included in approval and GitOps diff, preserved by legacy clients and normal configuration backup/restore. Snapshot assignment is intentionally independent (no automatic registry-to-live updates). Fleet propagation of the registry itself is out of scope; materialized runtime clusters remain the deployment contract. Fresh CI and independent review required.

- Independent HTTP(S) real-server catalog: reviewed named address/description templates, bounded IDs and capacity, strict no credentials/query/fragment origin validation, revisioned persistence, GitOps diffs and legacy preservation. Assignment creates an explicit destination snapshot; no implicit runtime updates or fleet object registry claimed. Fresh CI required.

- Real-server catalog persistence acceptance: the shipping real API harness now checks read-only GitOps planning, role and CSRF gates, unapproved draft isolation, independent approval and revision advancement, actual traffic forwarding, independent template edits, authorized rollback, invalid approval refusal, deletion without rewriting assigned destination snapshots, legacy payload preservation and survival of real process restart. This is a test implementation, not a successful execution claim; fresh CI and independent review remain mandatory.

- Reusable service-group templates reference existing real-server and optional monitor profile IDs with independent per-member weights and roles. Review-time validation prevents dangling references even for legacy clients that omit the catalog. Materialized clusters are independent approved snapshots; global live binding and fleet template distribution are not claimed. Exact-head acceptance pending.

- Guided HTTPS cookie persistence: native encrypted YARP Cookie policy, host-only __Host- cookie name derived from cluster ID, HttpOnly, Secure Always, Lax/Strict SameSite, browser MaxAge 1–1440 minutes and explicit Redistribute or Return503Error behavior. Reviewed config and runtime filter enforce the opt-in reserved namespace. No authentication, server-side expiry or cross-node key-scope guarantee claimed. Exact-head tests and independent acceptance pending.

- Expiring HTTPS affinity: guided secure-cookie editor now selects `GatewayCoreExpiringCookie`, with server-enforced authenticated expiry and cluster/cookie/lifetime purpose binding, explicit HTTPS-only request gate and existing drain/health eligibility. Prior native Cookie configurations continue to work. Tests exercise independent Data Protection providers with shared disposable keys, unrelated cluster/application rejection and expired/tampered token rejection; real HTTPS endpoint checks select the new policy. Actual cross-host authorized key provisioning, rotation/revocation continuity and physical failover still require acceptance; no production key files copied or created.

- Fleet ADC object snapshot: the controller signs the approved disabled destinations, monitor profiles, real servers and service-group catalog along with the materialized routes/clusters. The receiver uses the same pure draft contracts before reserving a sequence or staging bytes, rejects dangling references and refuses omission of nonempty node-local sections. Legacy empty sections remain compatible; explicitly reviewed empty sections can remove objects. Signature and rollback include the complete snapshot. Physical fleet rollout and independent acceptance remain outstanding.
