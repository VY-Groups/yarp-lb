# DNS TCP peer admission

Set MaxTcpSessionsPerClient to 1–32 in a reviewed signed DNS configuration (0 or absent preserves the existing global 32-session cap). The guided DNS draft form exports this field. The actual TCP socket peer is used; mapped IPv4 is normalized and IPv6 addresses share a /64 budget. A rejected connection is closed before parsing a frame or allocating a session task. All admitted leases are released on completion, disconnect or the existing five-second deadline. Shared resolvers and NAT clients share one limit: choose it using representative measured concurrent traffic and keep an independently tested rollback revision. Observe gatewaycore_gslb_dns_tcp_peer_limit_rejected_total without exporting client addresses. This limits concurrent TCP DNS application work only, not connection-rate floods, SYN floods, link saturation or fleet-wide quotas. Upstream mitigation remains necessary.
