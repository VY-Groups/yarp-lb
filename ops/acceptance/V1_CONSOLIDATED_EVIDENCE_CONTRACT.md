# GatewayCore v1 — consolidated evidence contract (review draft)

This document is an **execution contract**, not an assertion of passing tests. Run it against a frozen, independently reviewed commit. Keep #36 open for real-environment evidence; unfinished code and disposable integration tests stay on their software tickets. Do not store customer secrets, topology or private certificates in GitHub.

## Evidence manifest and decision rule

Create a private, append-only evidence directory with a manifest containing: UTC start/end, exact git SHA, artifact SHA-256, operator/reviewer identities, OS/runtime, redacted topology, command and exit code, expected/observed results, raw log/metric paths and SHA-256, issue ID, PASS/FAIL and remediation/retest. Preserve negative results. An absent or truncated artifact is **FAIL/NOT RUN**, never PASS. Independent reviewer must inspect raw evidence and exact-head GitHub Actions including **push runs on main**, not just PR checks. All examples below run in disposable test infrastructure unless explicitly marked site-only.

Baseline commands (record stdout/stderr and exit codes):

```sh
git rev-parse HEAD
git status --porcelain
dotnet --info
dotnet build engines/GslbDns/GslbDns.csproj -c Release
dotnet run --project tests/GslbAcceptance/GslbAcceptance.csproj -c Release -- "$PWD"
sha256sum <frozen-release-artifact>
```

Windows equivalent for artifact hashing: `Get-FileHash -Algorithm SHA256 <artifact>`. The release artifact must match the frozen source/release manifest. Do not invent a SHA when an artifact is absent.

## #36 site-only execution batch (after software entry gate)

1. Freeze release SHA, artifact hashes, offline dependencies, signed routing revision and rollback package. Obtain independent review and CAB change window; verify physical host separation, management/data-plane mTLS/IP isolation, CA non-replay boundary and signed-config parity. Missing any prerequisite = **NO-GO**.
2. Confirm real peak **Mbps versus MB/s** from switch/ISP graphs and measured peak RPS. For a verified 500 Mbps peak with 50% headroom, test **each gateway alone** at >=750 Mbps response-body **and** >=1.5 times actual peak RPS for **60 consecutive complete one-minute windows**, zero HTTP/transport errors, strict unchanged p99 and NIC/GC/log-loss gates. Do not aggregate the two gateways to satisfy a solo-node gate.
3. Follow `ops/automation/ONPREM_RUN_ORDER.md`: direct backend baseline, same-host-class reference baseline, one-change-at-a-time NIC characterization, gateway exploratory run, then strict solo-node acceptance. Run `python3 ops/capacity/limits.py --scenario <scenario.json> --profile <profile.json> --out <limits.json>` and `python3 ops/capacity/report.py --scenario <scenario.json> --results <generator-dir> --gateway-csv <node-telemetry.csv> --out <report.json>` with actual collected files. **Do not treat these placeholder filenames as pre-existing evidence.** Any missing 60-minute coverage, mismatched raw profiles, saturation, errors, p99 breach, drops or alert loss = FAIL.
4. On independent hosts, exercise graceful drain, kill, VIP/ECMP loss, blackhole/partition, failback, signed revision divergence, rollback rejection, certificate rotation, DNS delegation/DS/key rollover, CA/PKI/IdP/mail, live Collector/Grafana and alert delivery. Record actual absolute failed request counts and last-failure timestamp; never substitute lab timers for physical convergence.
5. Record signed CAB decision, independent reviewer and raw evidence hashes. A single failed or unrun applicable gate keeps **production NO-GO** and #36 open; any product defect reopens its development issue.

## Review and rollback contract

No direct main writes, self-approval, automatic issue closure or release publication by the development author. Independent reviewer checks exact PR head, relevant Windows/Linux CI and merged-main push workflow jobs before integration. For every failed step preserve original evidence, remediation commit, rerun SHA and changed gate result. Roll back only with a signed, approved revision preserving monotonicity and existing keys; never silently restore older authority epochs or Data Protection state.
