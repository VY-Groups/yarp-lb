# Approved on-prem physical acceptance order — NOT RUN

Production **NO-GO**. Real 10GbE *link speed* != measured peak. Obtain switch/ISP measured peak Gbps and RPS before any acceptance, along with response mix, HTTPS ratio, peak concurrency, new connections/s, CPU/RAM/NIC specs and p99 cap. 50% headroom near 10 Gbps cannot fit one 10GbE link. No thresholds are loosened and nothing in this repository runs on real hosts automatically.

1. **Generators directly to backends**: Prove generator, backend and network with real size mix, HTTP/HTTPS, concurrency and new-connections/s. Compare backend CPU/RAM/NIC and retransmits. **STOP** on baseline shortfall, dropped packets, rate-generator saturation or any errors.
2. **HAProxy reference baseline**: Same hardware class, ECDSA P-256 TLS, trusted CA/SNI, ALPN HTTP/1.1 vs h2 and persistent/fresh connections aligned with the scenario. Use the *same* weighted response paths. **STOP** unless baseline sustains required per-node peak+headroom; do not blame YARP before backend/reference can pass.
3. **NIC/OS one-change-at-a-time tuning**: Before AND after each approved modification collect `ethtool -g/-l/-x/-k/-S` for RX/TX rings, queues and offloads; RSS hash, per-CPU IRQ affinity/irqbalance and softirq counts; `net.core.rmem_max`, `wmem_max`, `net.core.netdev_max_backlog`; conntrack sizing/occupancy/timeouts; `ss -s`, `nstat -az`, `ip -s -s link`. Re-run identical HAProxy workload; **STOP / REVERT** on drops, driver errors, regressions or conntrack pressure. Read-only helper: `ops/tuning/collect_nic_baseline.sh NIC OUTPUT_DIR`. Never apply unexplained universal tuning constants.
4. **Gateway exploratory**: Ramp wrk/h2load separately through each isolated gateway to discover actual max RPS, Gbps and sockets. Verify the measured socket limit with `ops/capacity/limits.py`, not 10,000/65,536 guesses. **STOP** if measured Kestrel/NOFILE or network capacity cannot support input peak+headroom.
5. **Strict one-hour acceptance**: Each surviving node alone, >=60 complete windows and >=3600s common time; minimum body-Gbps >= `peak_gbps*(1+headroom)` AND RPS >= `peak_rps*(1+headroom)` EVERY minute, **zero HTTP/transport errors**, p99 STRICTLY below cap, all real GC/CPU/RAM/NIC telemetry. Reject `INFEASIBLE_LINK` (>90% of single NIC). Multiple generator hosts align windows and preserve raw weighted profile data. `oha` restarts each window, so add independent long-lived connection soak. **STOP** if any window fails.
6. **Physical node kill, then alert injection**: After the strict one-hour gate passes, test graceful drain/SIGTERM and abrupt gateway kill, VRRP VIP migration, physical host loss, blackhole/partition, ECMP behavior if used, signed config equality, rollback, no non-idempotent CA replay. Record last failure and absolute error counts. **Do not reuse lab 1.5 seconds.** VRRP physical failover will take several seconds (often 3–6s), to be measured. Then inject gateway down, 5xx, p99, unhealthy backend, log drops and certificate <14d in live Prometheus/blackbox, verify notifications and dashboard; **STOP** on any missing result.
