# Issue #34 paired allocation profile

`.github/workflows/issue34-paired-profile.yml` runs one serial job on one pinned GitHub-hosted Ubuntu 24.04 runner. It checks out the exact allocation baseline commit `d2b135f760e92fb2646ec5542d89a7dc309eb88c` and the candidate SHA, builds each lab, and executes three paired rounds in alternating baseline/candidate order. Within each revision sample it runs the same 75-VU, 45-second direct-backend phase and the same proxy phase with identical payload and connection reuse. A short proxy warmup is excluded from measurements.

Each measurement records request rate, p95/p99, requests and errors, request checks, allocated bytes, working-set change, Gen0/1/2 collection deltas, managed-heap change, and GC pause duration. The only pause-duration hook is a diagnostics-only overlay applied identically to each disposable `GatewayLab` checkout; neither production code nor the request middleware is modified by it. The report contains paired deltas, sample standard deviation and a Student-t 95% interval. Existing acceptance limits are retained: 30–115 seconds, at least 1,000 requests, <1% failed requests, >99.5% checks, p95 <2,500 ms and p99 <5,000 ms.

After the measured rounds, the workflow collects one 25-second `dotnet-trace` `gc-verbose` trace per revision with a 64 MiB EventPipe buffer. Linux `RLIMIT_FSIZE` caps child output files at 256 MiB, and the runner also verifies each trace stays under that limit. `gc-verbose` samples object allocations and records stack data. The trace is bounded diagnostic evidence for later human attribution; the report does not parse or automatically claim a particular code path caused an allocation.

Artifacts include raw per-run summaries and gateway counters, paired JSON report, trace files, and trace metadata. Keep them as isolated CI evidence. A single hosted runner is not production-scale evidence, and a measured improvement is not inferred if the paired interval includes zero. This workflow alone does not close issue #34: Windows parity, streaming and CA-signing POST/no-replay characterization, a defensible allocation-stack attribution, and an independently validated optimization without safety regressions remain acceptance work.
